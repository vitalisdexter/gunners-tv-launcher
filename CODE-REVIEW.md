# Focused code review

Reviewed manifests/permissions and exported component roles, provider readers and package-constrained deep links, network/timeouts/caches, football date/status/H2H handling, motion/focus/lifecycle paths, build/signing and recovery scripts. This is a bounded engineering review, not a security certification or claim that every path was exercised.

Confirmed fixes: reject oversized responses instead of partial decoding; close/disconnect HTTP streams; validate redirects and reject HTTPS downgrades; reject file artwork URIs; bound image dimensions and both-axis downsampling; bound weather JSON; omit provider exception messages from diagnostics; validate manual coordinates and key weather caches by location; replace the static strong match-dialog reference and dismiss on activity destruction; honor disabled forecast motion; declare explicit backup exclusions. JVM regression tests cover network policy, payload boundaries, image dimensions and location input. Existing H2H/player/status/navigation-policy tests remain.

Provider launch Intents retain owner-package restriction, component check, cleared selector/ClipData and reset flags. Real provider behaviour still needs device testing. HTTP is intentionally retained only for app-published artwork; weather/football require HTTPS. Native content-provider streams may block at the provider boundary, so remote HTTP timeouts are not a universal cancellation guarantee. Two artwork worker threads/cache behaviour remains inherited. No paid service, OAuth history access or private app scraping was introduced.

Only the unused old ArsenalWidget implementation was removed after checking references. Shared ArsenalSource/models/badges, horizontal utility paging, and conservatively retained disabled House/Promo scaffolding were not deleted wholesale. Upstream promotion/support screens and QR resources were removed; the owner's optional support link/QR was added separately in 1.0.1. Nonprivileged HOME priority limitations and the narrow optional helper remain documented.

1.1.0 review: the widget editor's height grew past the screen as rows were added, so it now uses a bounded focus-aware scroll viewport with a halo margin and post-reorder reveal. Football preferences are a versioned local model with empty defaults, main-club consistency, numeric-ID validation, count limits and no implicit starter fallback. Search results are filtered by football sport/UID (not search GUIDs); player/profile responses must match the requested football ID. National-side choices use reported metadata, never citizenship guessing. Search/profile tasks run off the UI thread, cancel on editor dismissal and discard stale results; football schedule work is isolated from weather/content workers and checks for changed selections between requests.

Media session connection callbacks and active-widget-only retry handle listener binding/revocation. A playing session outranks buffered/paused metadata, empty display titles fall through, and controls use published capabilities (including media-button toggle). Unsupported controls cannot take focus. Remote/content artwork has byte/dimension limits; file URIs are rejected. No additional runtime permission/library, notification-content processing or provider background-play workaround was added. JVM tests establish model/policy behaviour; they do not establish physical TV focus or YouTube background playback.
